```text

```

完成任务后记录：

```text
实际修改：

Error：通过 / 不适用 / 失败
```

`不适用` 必须说明原因；涉及可见模块时四态不得标记为不适用。时间是执行预算，不是以牺牲测试换取的截止时间。

## 2. 模块完成门禁

每完成一个可见模块，必须同时满足：

- 主流程可运行。
- Loading 可主动触发且不会无限等待。
- Empty 有明确说明与恢复入口。
- Error 有可理解提示、诊断记录与重试/降级。
- 单元测试、集成测试、Release build 和边界脚本通过。
- 对应 Fixture/Replay 通过并输出 Harness Compliance Report；不适用项说明理由。
- 仅当本任务全部验收通过，才把 `[ ]` 改为 `[x]`；否则保持未勾选并记录阻塞。
