# Windows 桌面精灵 PRD

> 文档状态：MVP 规划稿  
> 产品代号：AI Spirit（Windows）  
> MVP 目标：先验证“用户愿意让一个可爱的精灵长期留在桌面上并主动与它互动”。

## 1. 产品定位

AI Spirit 是一款 Windows 桌面陪伴应用。它以透明、无边框、置顶但不打扰的桌面精灵为核心，让用户获得轻量陪伴、个性表达和未来可扩展的专注辅助体验。

它不只是聊天机器人，也不是效率工具集合。聊天是后续重要的陪伴能力，但首版只建立最小陪伴闭环：启动精灵 → 看见状态变化 → 拖动/点击互动 → 切换外观 → 下次启动恢复。

长期方向：

- 陪伴：由画师创作的动态角色形象、表情、动作、换装和轻互动。
- 聊天：用户主动唤起对话，与精灵进行有上下文、可中止的文字交流。
- 专注：番茄钟、勿扰状态、阶段反馈。
- 兴趣内容：在用户明确授权后读取指定来源，生成个性化内容。
- 成长：通过使用与互动解锁装扮和动作，但不制造强制签到压力。

## 2. 目标用户与痛点

### 2.1 核心用户

1. 16–35 岁、长期使用 Windows 的学生、创作者、程序员和办公室用户。
2. 喜欢可爱角色、桌面美化、换装和收集的人。
3. 独自使用电脑时间较长，希望获得低压力陪伴的人。
4. 未来的扩展用户：需要番茄钟辅助专注，但排斥严肃效率软件的人。

### 2.2 用户痛点

- 桌面工具功能感强、情绪价值弱，难以长期留存。
- 传统桌宠容易遮挡工作、抢焦点、耗资源或无法快速隐藏。
- 陪伴类 AI 常要求持续聊天，互动成本高。
- 换装与个性化通常依赖账号、商城或复杂养成，首次体验过重。
- 屏幕读取类产品容易引发隐私焦虑，用户不清楚读取了什么。

### 2.3 核心价值主张

“一只安静、可爱、可掌控的桌面精灵：需要时陪你，不需要时不打扰。”

## 3. MVP 假设与成功信号

### 3.1 待验证假设

- 用户愿意让精灵连续常驻至少 30 分钟。
- 用户能在 1 分钟内完成首次互动，无需教程。
- 用户会主动拖动、点击或更换至少一次外观。
- 用户认为精灵不会明显遮挡或干扰正常工作。

### 3.2 MVP 成功信号

- 主流程任务完成率 ≥ 95%。
- 冷启动到精灵可互动 ≤ 2 秒（开发基准机，Release、本地资源）。
- 空闲常驻 CPU 平均占用 ≤ 2%，内存目标 ≤ 150 MB。
- 10 次连续启动、退出、恢复位置无崩溃，位置始终回到可见屏幕范围。
- 至少 5 名目标用户中 4 名无需指导完成拖动、互动、换装和退出。

## 4. 核心用户旅程

### 4.1 首次启动

1. 用户启动应用。
2. 精灵在主屏幕右下安全区域出现，播放短暂入场动作。
3. 一个轻量气泡提示“拖动我 / 右键查看更多”，数秒后自动消失。
4. 用户点击精灵，精灵播放回应动作和短气泡。
5. 用户拖动精灵到喜欢的位置。
6. 用户右键打开菜单，进入外观面板并切换一个外观。
7. 用户关闭面板继续工作；应用记住位置和外观。

### 4.2 再次启动

1. 应用读取本地设置。
2. 精灵恢复上次外观和位置；若显示器布局变化，则自动回到当前屏幕安全区。
3. 精灵进入空闲动画，不弹教程、不抢焦点。

### 4.3 临时不打扰与退出

1. 用户在右键菜单选择“隐藏精灵”或使用托盘菜单。
2. 精灵隐藏，但托盘入口仍可恢复。
3. 用户可从托盘明确选择“退出”，应用完全结束。

## 5. MVP 功能列表

### P0：必须完成

| 功能 | 范围 | 用户价值 |
|---|---|---|
| 单实例启动 | 重复启动时激活已有实例 | 避免出现多只精灵 |
| 桌面精灵窗口 | 透明、无边框、可置顶、默认不占任务栏 | 形成桌宠基本体验 |
| 动态精灵 | loading、idle、react、drag 四种动画状态；idle 至少包含呼吸/眨眼 | 精灵持续有生命感 |
| 点击互动 | 点击触发回应动作与本地文案气泡 | 完成最小陪伴反馈 |
| 拖动与位置恢复 | 支持多显示器、DPI 缩放与可见区域校正 | 可摆放且不会“丢失” |
| 右键菜单 | 外观、隐藏、关于、退出 | 操作可发现、可控制 |
| 托盘入口 | 显示/隐藏、退出 | 隐藏后仍能找回 |
| 基础形象切换 | 至少 2 套本地画师角色包，每套包含完整动态状态，切换后立即生效 | 验证个性化与画师内容管线 |
| 本地设置 | 保存位置、外观、首次引导状态 | 建立跨会话闭环 |
| 异常降级 | 资源损坏、设置损坏时回退默认状态 | 主链路不崩溃 |

### P1：MVP 验证后

- 番茄钟：25/5 默认周期、开始/暂停/跳过、阶段反馈、勿扰动作。
- 画师角色包导入、更多服装、表情和动作包。
- 开机启动开关。
- 音效和音量开关。
- 本地轻量成长记录。

### P2：明确授权后再做

- 精灵聊天：文字输入、流式回复、会话上下文、停止生成、重新生成和历史管理。
- 兴趣来源绑定、内容摘要和个性化生成。
- 屏幕/前台应用感知。
- 本地或云端模型接入。
- 账号、跨设备同步和内容市场。

## 6. 功能黑名单

MVP 禁止实现：

- 未经明确授权读取屏幕、剪贴板、键盘输入、浏览历史、文件或麦克风。
- 后台静默截图、录音或上传任何用户内容。
- AI/云服务、账号、登录、支付、商城、广告、遥测和自动更新。
- 聊天、番茄钟、兴趣读取、内容生成、复杂养成、任务签到。
- 强制开机启动、无法关闭的置顶、诱导留存和高频通知。
- 从远程 URL 动态执行脚本或下载未校验资源。
- 精灵窗口抢占键盘焦点、阻止用户切换窗口或覆盖系统关键区域。
- 为赶进度绕过服务层直接调用系统 API、存储或未来 AI SDK。

## 7. 状态与边界

- `booting`：读取本地资源和设置；展示静态占位或 loading 动画。
- `ready.idle`：正常常驻。
- `ready.interacting`：点击反馈中，完成后回到 idle。
- `ready.dragging`：跟随指针；释放后校正并保存位置。
- `hidden`：窗口隐藏、托盘存活。
- `degraded`：资源或设置异常，使用默认外观和默认位置。
- `fatal`：仅用于无法创建窗口等不可恢复问题；显示可理解提示并允许退出。

桌宠本身没有业务“空数据”；外观面板为空时必须展示空状态，并提供“恢复内置外观”。

## 8. 验收标准

### 8.1 主流程

- Windows 10 22H2 与 Windows 11 上可启动，且同一用户会话仅一个实例。
- 精灵背景透明、无系统边框，不在普通 Alt+Tab 列表中制造多余窗口。
- 点击精灵后 100 ms 内出现视觉反馈，动作完成后回到 idle。
- 可拖到任意显示器；松手后至少 25% 精灵区域留在工作区内。
- 切换外观即时生效；重启后外观与位置恢复。
- 两套画师角色包均能播放 idle、react、drag 动画；切换形象不会丢失角色状态或闪出空白帧。
- 隐藏后可通过托盘恢复；退出后进程结束且不残留后台任务。

### 8.2 加载、为空、报错

- 设置读取期间不白屏、不闪现不透明矩形，最长 2 秒后进入 ready 或 degraded。
- 外观列表为空时显示空状态，程序不崩溃，用户可恢复内置外观。
- 设置 JSON 损坏时隔离损坏文件、使用默认设置，并记录本地诊断事件。
- 某个动画资源缺失时使用默认静态精灵，点击、拖动、隐藏和退出仍可用。
- 保存设置失败时显示一次非阻塞提示；内存状态继续工作，退出不死锁。

### 8.3 非功能

- Release 空闲 10 分钟 CPU 平均 ≤ 2%，内存目标 ≤ 150 MB。
- 不联网时功能完整；网络请求数量应为 0。
- 日志不得包含用户输入内容、屏幕内容或个人文件路径。
- 核心服务具备单元测试；主流程与四态具备集成测试或可重复手工验收脚本。

### 8.4 画师资产交付

- 每套角色包必须声明角色 ID、名称、作者/版权信息、画布尺寸、锚点、缩略图和动画清单。
- MVP 必需动画为 `idle`、`react`、`drag`；`loading` 可复用静态预览，`fallback` 必须存在。
- 画师交付透明背景源图；程序侧不得依赖裁切画师签名或未授权修改作品。
- 同一角色各动画使用统一画布、脚底锚点与视觉比例，切换状态时角色不得明显跳位。
- 资源包缺文件、格式不支持或版本不兼容时不得加载，保留当前可用形象。

## 9. MVP 之外的产品决策点

进入聊天前需单独确认：入口与窗口形态、模型来源、上下文长度、历史是否默认保存、停止生成、内容安全、离线降级和费用上限。进入番茄钟前需验证：计时入口、精灵提醒强度、系统通知策略、暂停/恢复语义。进入兴趣读取前需单独完成隐私评审：数据来源、授权粒度、本地/云端边界、保留周期、撤回与删除机制。
